## premisesFalse
- §9 U27 claims the phone cell must be read as `typeof cell.value === "number" ? String(Math.round(cell.value)) : cell.text` because `cell.text` gives "2.55713E+11". FALSE for the installed exceljs 4.4.0. Cell.text is `this._value.toString()` (node_modules/exceljs/lib/doc/cell.js:232-234), and NumberValue.toString is `this.model.value.toString()` (:445-447). Number#toString never uses exponent form below 1e21, so cell.text of 255713000000 is '255713000000'. '2.55713E+11' is Excel's DISPLAY of a 12+-digit number in General format, and Excel writes the displayed text when a sheet is SAVED AS CSV or copied to the clipboard. The lossy hazard is in the CSV remedy and in paste (U25), not in the XLSX read. The proposed expression also has defects of its own. (a) Math.round on EVERY numeric cell corrupts genuine decimals in other columns: the reader cannot know which column is the phone until U28 maps it. (b) `cell.text` renders a Date as 'Thu Oct 01 2026 03:00:00 GMT+0300' (DateValue.toString, cell.js:577-579). (c) It drops a formula result of 0, because `this.model.result ? … : ''` (cell.js:877-879). (d) It reads a merged slave as the master's value. CORRECTION: one typed `xlsxCellText(value)` switch. An integer is written exactly. A float-noise value within 1e-3 of an integer, with |v| ≥ 1e6, is rounded. A genuine decimal is kept as String(v). A Date becomes ISO YYYY-MM-DD. A formula falls through to its cached result (0 → '0'; none → '' plus a note). Rich text is concatenated, a hyperlink reads its display text, an error is '' plus a note, a merge slave is '' plus a note. An Excel-shortened value (the text '2.55713E+11', or an integer ≥1e11 divisible by 1e6) is kept verbatim and FLAGGED by line and column, never 'repaired'.

## risks
- The orphan action. Shipping readXlsxContactsAction without a caller reds test:orphan-actions (orphan-actions.test.mts:103-122), which test:all runs. The action is deferred to U30 by design. ⛔ Do not dodge the guard by renaming the function or adding a KNOWN_ORPHANS row.
- The remedy itself can corrupt data. Excel's Save-as-CSV and clipboard paste write 12+-digit General numbers as '2.55713E+11'. The copy now carries the format step, but an operator who skips it will produce such rows. U25 must flag them (EXCEL_SHORTENED_TEXT) rather than let them fall into a generic 'too short' sentence.
- A stranger's number. An XLSX re-saved from a CSV that already held '2.55713E+11' stores the NUMBER 255713000000, which parseTzNumber accepts as a valid Yas number. U27 only FLAGS it (the excel_shortened note with line and column). U30 must turn flagged phone cells into `invalid`, or a first-party basis (U33) could import and later market a stranger.
- The single production instance also serves bets. exceljs's non-streaming load holds the whole workbook model in the heap and parses in synchronous SAX chunks. Mitigations: the 700 KiB cap, a real capped inflate of every entry (bomb and forged-size proof), the row cap and one read in flight. The streaming reader is rejected because it spools PII to tmp. The builder must record measured ms and heap for the densest fixture in §3; if the parse exceeds ~1.5 s, the event-loop stall is a finding to raise, not to hide.
- Zip parity. Our walker and JSZip must see the same bytes. The pre-pass inflates EVERY entry, including docProps and xl/media, from the central-directory offsets exactly as JSZip does, and refuses zip64, encryption and unknown methods outright, so there is nothing for exceljs to inflate that the pre-pass did not.
- test:red-anchors classification. One write-call token in either suite, even in a comment or a regex literal (e.g. the §5.2 disk-touch regex), flips the harness to 'undeclared' and breaks the === 65 ceiling for every lane (red-anchors.test.mts:288, 304-306). Build such regexes by concatenation. exceljs `writeBuffer(` is safe.
- Tooling. These suites are regex-heavy, and the Write/Edit tools decode escapes. After writing, scan the new files for raw control characters (memory: reference_edit_tool_decodes_escapes). On Ali-Blade15 the CRLF checkout means the walker must normalise line endings before it detects directives.
- test:docs and test:guards-exist. §9 names the new suites by KEY until the commit that creates them, then the text is rewritten to full forms in the same commit. Any src docblock citing test:contacts-boundary needs the package.json key in that commit.
- Shape drift. If U25 is designed in parallel with a different ParsedContactsFile, the X22 'exactly one export type' assertion and isParsedContactsFile fail loudly. Reconcile then; never keep two.
- RECORDED, NOT THIS UNIT'S (platform-consistency rule, hand to the KYC/platform owner in §0 CARRIED). MAX_DOC_BYTES is 3 MiB (src/lib/id-documents.ts:88), and kyc-image.ts:37 only shrinks a photo below THAT. Any resized KYC data URL between ~780 KB and 3 MB is therefore refused by Next's 1 MB action ceiling with a framework 413, not with the uploader's own 'imageTooLarge' copy (kyc-doc-uploader.tsx:54).
