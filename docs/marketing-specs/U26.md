# U26 · The vCard reader: src/lib/contacts/vcard.ts (pure, client-safe, streaming). Folding and quoted-printable are handled in one walk, the format is version-aware, and cards are counted apart from rows

## premisesTrue
- Separate passes really do corrupt each other, in BOTH orders, and silently. (a) Unfold first (RFC 2425: strip CRLF plus one whitespace char), then join QP soft breaks: a QP continuation line that begins with a literal space is legal (RFC 2045 §6.7 rule 3 forbids only TRAILING whitespace), and it loses that space. `FN;ENCODING=QUOTED-PRINTABLE:Mama=` CRLF ` Asha Mwakalinga` reads as `Mama=Asha Mwakalinga` (or `MamaAsha…`) instead of `Mama Asha Mwakalinga`. (b) Join QP soft breaks first, over the whole text: every line ending in `=` gets glued to the next. That includes a 3.0 base64 PHOTO line ending in `==` padding (iPhone and Google exports put PHOTO last, right before END:VCARD) and a plain `NOTE:Lipa=`. The END:VCARD or TEL that follows is swallowed into the photo, so the card is never closed and its contact is lost. Only the property head knows whether a line is QP, which is why the rule has to live inside the one walk. No code exists yet; this is reasoning against RFC 2045, RFC 2425 §5.8.1 and RFC 6350 §3.2.
- `itemN.` group prefixes are real and common: Apple and Google exports write `item1.TEL;type=pref:…` with `item1.X-ABLabel:…`, and WhatsApp shares `item1.TEL;waid=…:`. A reader that keys on the raw name sees `ITEM1.TEL` and drops the number.
- Bare 2.1 params are real. Outlook and Nokia write `TEL;CELL;PREF:` and `FN;CHARSET=UTF-8;QUOTED-PRINTABLE:` (a bare encoding token), so a bare token is a TYPE value unless it is an encoding token (QUOTED-PRINTABLE/BASE64/B/8BIT/7BIT).
- 4.0 `TEL;VALUE=uri;…:tel:+255-…` is real (RFC 6350 §6.4.1 example `tel:+1-555-555-5555;ext=5555`).
- The module must be pure and client-safe, because OD29 (docs/MARKETING-CAMPAIGN-AND-CONTACTS-SETUP.md:1020) parses vCard in the BROWSER. Importing `src/lib/tz-msisdn.ts` is safe: `src/components/ui/phone-input.tsx:1` is "use client" and imports it at :20, tz-msisdn imports only `./payment-providers`, and payment-providers.ts:20 states it has no imports and must never gain one.
- Per-row helpers are provably built once. `tzTableBuildCount()` (tz-msisdn.ts:190,200) lets the suite assert the NDC index is still built exactly once after a 20,000-card parse (§3c.4, docs:847-849).
- Cards are not rows. A card with no TEL, or one cut off at EOF or at the next BEGIN, produces no row, so '12 cards, 9 rows' needs its own counters.
- The contact-book columns the reader feeds exist: `MarketingContact` has `rawInput`, `displayName`, `email`, `tags String[]` and `notes` (prisma/schema.prisma:3319-3350). There is no consent column to fill from a file, and none should be: U31/U33 say consent is never written by an import path.
- An in-process `--prove-red` with no file-writing call is outside test:red-anchors' undeclared-harness ratchet (scripts/red-anchors.test.mts:288 `UNDECLARED_CEILING = 65`, :306 `isInProcess`). The tracker's §1b accepts the same class (scripts/marketing-setup-plan.test.mts:161).
- red:all and test:all enumerate package.json structurally (scripts/red-all.mjs header; scripts/test-all.mjs:44-46), so there is no hand list to update. predeploy IS a literal chain (package.json:300), so the new key must be added there.
- The pairing is S12 = U25 · U26 (docs:2451), and the board row is U26 · pure · ⬜ · `test:contacts-import` (docs:557).
- §3c binds U26 to stream: "U25/U26 parse a stream into batches" (docs:842-843) and "every import unit carries a fixture of ~40 rows alongside its large one" (docs:852-853).

## premisesFalse
- 'RFC 2425 folding' as THE fold rule (docs:2104) is wrong for vCard 2.1. 2.1 §2.1.3 folds the RFC 822 way: CRLF before whitespace is removed and the whitespace is KEPT. RFC 2425 §5.8.1 (3.0) and RFC 6350 §3.2 (4.0) remove CRLF plus exactly ONE whitespace char. Correction: the fold is version-aware. A 2.1 card keeps the whitespace; 3.0/4.0, and any card before its VERSION line is seen, drop one char. Pin both with fixtures: 3.0 `FN:Mwaka`+CRLF+` linga` → `Mwakalinga`; 2.1 `NOTE:Mwaka`+CRLF+` linga` → `Mwaka linga`.
- The RED 'split the two continuation rules into two passes → red' (docs:2107) proves only half if it is planted in one order against one fixture. Each order corrupts a DIFFERENT input: unfold-first eats the leading space of a QP continuation, and QP-first swallows the TEL/END after a base64 `==` or `NOTE:x=` line. Correction: two plants (both orders) and two fixtures, each required to fire its own assertion.
- A plain 4.0 `TEL;VALUE=uri:tel:+255712345678` is NOT a discriminating fixture. `parseTzNumber` already reads it as ok: `hadPlus` is `trimmed.startsWith("+")` (src/lib/tz-msisdn.ts:249) and is simply false, non-digits are stripped (:250), and `255712345678` becomes the national number (:268). A reader that forgets the scheme passes. The real damage is (1) URI params: `tel:+255-712-345-678;ext=101` gives 15 digits, so too_long (:279), and a good number is refused; (2) a foreign `tel:+254712345678` misses the foreign branch (:259 needs hadPlus) and is judged too_long. Correction: the V4 fixtures use `;ext=101` and `+254`, plus a CONTROL asserting the plain form is ok either way, so nobody 'simplifies' the fixture back.
- 'preferred-first' (docs:2106), taken literally, is wrong for SMS. A card's preferred TEL is often a work landline (`TEL;TYPE=work;PREF=1:+255 22 212 3456`). Picking it turns a reachable contact into an `invalid` row and throws away the mobile on the same card. Correction: order every TEL preferred-first (4.0 PREF=n ascending; 3.0 type=pref and 2.1 bare PREF rank 1; absent ranks 101; ties keep document order), keep them all in `phones`, and set `phone` = the first one `isSendableTzNumber` accepts (tz-msisdn.ts:342). If none is sendable, fall back to `phones[0]` so U30 still prints its refusal sentence.
- The §9 text omits streaming, but §3c.2 (docs:842-843) requires U26 to parse a stream. Correction: the API is a push/end chunked reader. `parseVcardText` is only sugar over it, and the guard proves chunked output equals whole-text output at every split point.
- `test:contacts-import` does not exist: no package.json key (only `test:contacts-page`, package.json:247) and no `scripts/contacts-import.test.mts`. test:guards-exist (§11a.4, docs:2517) hard-fails as soon as vcard.ts's docblock cites it. Correction: `test:contacts-import`, `red:contacts-import` and the predeploy entry land in the SAME commit as vcard.ts.
- `src/lib/contacts/` does not exist, and `ParsedContactsFile` / `detectFormat` (U25 docs:2098, U27 docs:2114) exist nowhere in src. U26 cannot import a shared shape. Correction: U26 ships its own grid adapter type `VcardGrid`, which U25's `ParsedContactsFile` must accept structurally, and U25's `detectFormat` must import `looksLikeVcard` rather than write a second sniff.

## apis
- export const MAX_KEPT_LINE = 65_536 — the cap on any KEPT logical line's value (NOTE etc.). Beyond it the value is truncated and stats.truncated++. Unkept properties (PHOTO/LOGO/SOUND/KEY/ADR/LABEL/X-*…) are NEVER buffered: the walk keeps only their head plus whether the last physical line ended in `=`.
- export const VCARD_GRID_HEADERS = ["Name", "Phone", "Email", "Tags", "Notes"] as const — the English headers the grid adapter emits. U28's CONTACT_FIELDS aliases MUST map every one of them (recorded dependency).
- export type VcardParam = { readonly name: string /* upper-cased; a bare 2.1 token becomes "ENCODING" if it is one of QUOTED-PRINTABLE|BASE64|B|8BIT|7BIT, else "TYPE" */; readonly values: readonly string[] /* split on unquoted commas, quotes removed, case kept */ }
- export type VcardProperty = { readonly group: string | null; readonly name: string /* upper-cased, group stripped */; readonly params: readonly VcardParam[]; readonly value: string /* raw: still escaped/encoded */ }
- export function parseContentLine(logical: string): VcardProperty | null — splits name/params from value at the first `:` NOT inside double quotes (so `ADR;LABEL="Box 1: Dar":…` works), params on unquoted `;`, the group on the first `.` of the name token, case-insensitive. Returns null for a line with no unquoted `:` (counted as a stray line, never thrown).
- export function decodeQuotedPrintable(raw: string, charset: string | null): { text: string; warnings: number } — `=XX` (either case) becomes a byte. A char above 0x7F is re-encoded as UTF-8 bytes. An invalid `=` sequence is kept literally and warnings++. Any leftover `=`CRLF/`=`LF soft break is removed. Bytes are decoded with `new TextDecoder(charset ?? "utf-8", { fatal: false })`. An unknown label (RangeError) falls back to utf-8 with warnings++.
- export function unescapeText(raw: string): string — 3.0/4.0 text escapes `\\`→`\`, `\,`→`,`, `\;`→`;`, `\n`/`\N`→newline. Applied to FN/N components/ORG/NOTE/CATEGORIES after decoding. Structured values (N, ORG) are split on UNESCAPED `;` FIRST, then each component is decoded/unescaped.
- export function telValue(raw: string): string — trims. If it starts with `tel:` (case-insensitive, with or without VALUE=uri), strips the scheme and cuts at the first `;` (URI params such as ;ext=, ;phone-context=). Otherwise returns the value as written: separators are kept for rawInput, and the pre-flight's parseTzNumber decides.
- export type VcardRow = { readonly card: number /* 1-based ordinal over ALL top-level cards, skipped ones included: the row number U30 prints */; readonly displayName: string | null /* FN; else N assembled as prefix given additional family suffix; else ORG's first component; whitespace collapsed and trimmed */; readonly phone: string /* chosen: first preferred-ordered TEL that isSendableTzNumber accepts, else phones[0] */; readonly phones: readonly string[] /* every non-empty TEL via telValue, preferred-first */; readonly email: string | null /* first EMAIL, preferred-first */; readonly tags: string | null /* every CATEGORIES value, unescaped, joined with ",": U28/U29 split it with the same splitter as a CSV Tags cell, so there is one splitter */; readonly notes: string | null /* first NOTE, newlines kept */ } — exactly these keys. The reader never invents consent or source.
- export type VcardSkip = { readonly card: number; readonly reason: "no_phone" | "unterminated"; readonly displayName: string | null } — never a phone number (§5.14). `unterminated` covers EOF inside a card, and a BEGIN:VCARD arriving in an open card whose previous property was not an empty-valued AGENT.
- export type VcardBatch = { readonly rows: readonly VcardRow[]; readonly skipped: readonly VcardSkip[] }
- export type VcardStats = { cards: number; rows: number; skippedNoPhone: number; skippedUnterminated: number; strayLines: number; extraPhones: number /* cards with >1 TEL */; truncated: number; decodeWarnings: number; peakKeptChars: number }
- export interface VcardReader { push(chunk: string): VcardBatch; end(): VcardBatch; stats(): VcardStats } and export function createVcardReader(): VcardReader. THE ONE WALK: physical lines are split on CRLF|LF|CR. A chunk-final CR is held so that a following LF in the next chunk is swallowed, and the carry after the last terminator waits for the next push. A logical line is emitted only when the NEXT physical line is seen (or at end()), so chunk boundaries cannot matter. The decision for each next physical line L, in order: (1) if the pending property's head is complete, its params say QP (ENCODING=QUOTED-PRINTABLE or a bare QUOTED-PRINTABLE, in any version), its value trimmed of trailing SP/HTAB ends in `=`, and L is not `END:VCARD` (trimmed, case-insensitive): drop that `=` and append L VERBATIM, leading whitespace included; (2) else if L starts with SP/HTAB, it is a fold: append L (2.1 card) or L.slice(1) (3.0/4.0, or before VERSION is seen); (3) else emit the pending line and start L. A blank line emits the pending line and is otherwise ignored. A leading U+FEFF is stripped once. Card logic: BEGIN:VCARD opens card n+1, or nests (depth++) when the open card's last property was an empty-valued AGENT. Nested content is ignored and never leaks a TEL into the outer card; otherwise the open card closes as unterminated. END:VCARD at depth 1 finalises the card; outside any card it counts as a stray line. Finalise: no non-empty TEL → skip no_phone; else build a row. 2.1/3.0 ENCODING=BASE64|B text values are decoded via atob plus TextDecoder(charset).
- export function parseVcardText(text: string): VcardBatch & { stats: VcardStats } — one push plus end() on createVcardReader(); there is no second implementation (§3c: one code path for 40 and 150,000 cards).
- export function looksLikeVcard(head: string): boolean — true iff the first non-blank line (after U+FEFF and leading whitespace) is `BEGIN:VCARD` case-insensitively, trailing spaces allowed. ⭐ The ONE vCard sniff: U25's detectFormat imports it, so a .txt of vCards is vCards.
- export function assertVcardCounts(stats: VcardStats): void — throws `Error("vCard counts do not add up: 12 cards ≠ 9 rows + 2 skipped")` (counts only, never a number) unless cards === rows + skippedNoPhone + skippedUnterminated. Exported so the suite can prove it throws (the assertPreflightAdds pattern, U30).
- export function describeVcardCounts(stats: VcardStats): string — the one 'sayable' sentence, in English admin chrome (§5.13: not a heading, so no gloss), with en thousands separators and correct singulars. E.g. `12 cards, 9 rows — 2 cards have no phone number; 1 card is cut off before its end.` / `1 card, 1 row.`
- export type VcardGrid = { readonly headers: typeof VCARD_GRID_HEADERS; readonly rows: readonly (readonly string[])[]; readonly rowNumbers: readonly number[] /* = card ordinals */; readonly unreadable: readonly { readonly rowNumber: number; readonly reason: string }[] /* skipped cards with a sentence: 'This card has no phone number.' / 'This card is cut off before its end, so it was not read.' */ } and export function vcardBatchToGrid(batch: VcardBatch): VcardGrid — the bridge to U25's ParsedContactsFile and U30's `unreadable` bucket; null fields become "".

## risks
- It cannot be verified live on its own. Nothing imports vcard.ts until U30/U32's dialog, so it is not even in the production bundle. The row can reach 🔵 (commit) but not ✅ until a .vcf is parsed on www.50pick.tz through U32. Say so in the §1 notes rather than inventing a live check.
- The reader works on decoded strings. If a file is folded in the middle of a multi-byte UTF-8 sequence (RFC 6350 §3.2 warns that simple generators do this), the outer TextDecoder has already turned it into U+FFFD, and a non-QP 8-bit 2.1 file (CHARSET=ISO-8859-1 without QP) is mangled the same way. Names only, never phone digits (ASCII). UTF-16 exports (some Windows tools) need a BOM sniff (FF FE / FE FF) before TextDecoderStream; that is the caller's job (U25/U32). Record it there.
- The `=` CRLF `space` ambiguity is resolved the RFC 2045 way: the space is content. An exporter that both soft-breaks AND folds would leave one extra space, which displayName's whitespace collapse absorbs.
- CRLF checkout (core.autocrlf=true here) rewrites the line endings of any fixture FILE, so the LF-only and CR-only fixtures must be built in code with explicit joiners. The Edit/Write tools decode escapes (memory: reference_edit_tool_decodes_escapes), so build vCard backslashes with String.fromCharCode(92) and keep the §V9.1 control asserting that the backslash is present.
- test:search-adoption fails any src file containing `.toLowerCase().includes(` outside src/lib/search (scripts/search-adoption.test.mts:71-75). Match TYPE tokens with an upper-cased Set and `.has`, not includes.
- The suite is shared with U25–U32. Keep U26's sections prefixed §V and its red block in-process. A write call anywhere in scripts/contacts-import.test.mts drops `red:contacts-import` out of the in-process class and breaks test:red-anchors' ratchet (65) for every lane.
- package.json and the plan doc carry U20's uncommitted edits in this worktree. U26's commit must be `git commit --only` after U20 ships, and `git fetch && git merge --no-edit origin/main` must run before the push (§0 TRAPS).
- Performance at 150k cards: the split sweep in §V7.1 is O(L²) per fixture, so keep sweep fixtures ≤ ~2 KB. The reader must avoid repeated string concatenation of unkept values, and holds at most the longest PHYSICAL line (a 4.0 PHOTO data: URI on one unfolded line is held once). §V8.2 is capped at 20,000 cards to keep the battery light on Ali-Blade15.
- Two policy choices are the operator's to see, not to configure: an unterminated card is SKIPPED (a hand-edited file missing its last END loses that contact, visibly in the count sentence), and a card yields ONE row (extra numbers are counted in stats.extraPhones and dropped; msisdn is @unique per person). describeVcardCounts should be extended by U30 if extraPhones needs saying.
- phone choice reads the CURRENT NDC table. If TZ_MOBILE_NDCS changes (U2's reviewed date), re-importing the same card could choose a different number. This is accepted and documented in vcard.ts's docblock.
- §3c.1 (the file never arrives through a server action; docs:839-841) and OD29 (browser parse, post rows; docs:1020) read differently. The reader is pure, so it serves either. OD29 governs, and U26 adds no upload path.
