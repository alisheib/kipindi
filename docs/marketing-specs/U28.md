## risks
- SAMPLE NUMBERS MAY BELONG TO REAL PEOPLE. Tanzania has no fictional number range, so any ok number may be a live subscriber. If the operator leaves the 3 example rows in, an import under a first-party basis (U33) writes GIVEN for a stranger, which is unsolicited marketing (§5.1). U28 makes them known (SAMPLE_MSISDNS, §F14), but only U30's refusal makes them harmless. U30's §9 text must say so in U28's commit. Until U30 there is no importer, so nothing is exposed today.
- EXCEL DESTROYS 12-DIGIT NUMBERS ON A CSV SAVE ('2.55712E+11'). U28's own samples are Excel-safe (§F13), but numbers the operator types are not, and U27's 'save it as CSV' remedy invites exactly that loss. U25 or U30 should name a scientific-notation phone cell in its own sentence, and U27's remedy should say 'format the Phone column as Text first'.
- WEAK ALIASES CAN STILL MIS-MAP when a file has no strong phone column, for example 'Namba | Jina' where Namba is the serial. Every row then goes invalid with 'digits cut off'. U30 should notice when every row in the mapped Phone column fails and suggest remapping.
- The Write/Edit tools decode escapes (memory). The vCard escaper's backslash sequences and the BOM must be built with String.fromCharCode(92) and String.fromCharCode(0xfeff), and the written files scanned for the expected bytes before the suite runs. test:encoding catches invalid UTF-8 but not a wrong backslash.
- The tag rules become a contract across units. Storage keeps the first spelling and de-duplicates case-insensitively within a row, so 'VIP' and 'vip' on DIFFERENT rows are still two stored spellings. U21's tag pill and U31's MERGE must group by tagKey or the filter shows two pills for one tag.
- §F20's one-list grep polices hand-chosen distinctive tokens: the underscore keys and the Swahili aliases. A second list built only from common words (name, email, notes) would pass, because those words appear legitimately in UI code. Stated, not hidden; U34's own guard must assert it imports contactExportHeader.
- The vacuous population of §F21 (0 entrances) reads like a pass. The planted-entrance control is mandatory, and the printed count must be read, not assumed (memory: 'Not applicable is the most dangerous silent verdict').
- Lower-casing emails changes the stored spelling compared with the file. U34's 'export, then re-import, changes 0' still holds because the export writes the stored lower-case value, but U31's 'changed?' comparison must also compare lower-cased.
- unguardCell also strips a leading ' before = + - @ in FOREIGN files, so a name genuinely spelled "'+…" loses its apostrophe. Negligible, and written in the file's comment.
- The ':::' split and the '* '-label drop go beyond the plan's three separators. A tag that literally contains ':::' would be split. This was decided on the standing delegation of technical calls because Google Contacts is the most likely source file.
- Repo-wide gates. test:guards-exist needs the package.json key in the same commit as the first docblock citing test:contacts-import. test:docs forbids writing the script path in docs before it exists. test:red-anchors needs no write-call token anywhere in the suite file.
