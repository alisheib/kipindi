## Premises found false (8)

- FALSE: '⭐ bought / third-party list writes UNKNOWN' (§9 U33 line 2176) and OD9's 'its rows carry UNKNOWN… must ship in its OWN migration ONE COMMIT before U33' (line 957). MessagingConsentStatus is GIVEN|WITHDRAWN (schema.prisma:3129-3132; store.ts:387). U18a deliberately declined to widen the ledger's enum (schema.prisma:3287-3292) and put UNKNOWN on ContactConsentState instead. A ledger UNKNOWN row would also become a person's LATEST row and override a real GIVEN or WITHDRAWN. Decided: a third-party run writes NO ledger row. The absence is 'no consent' (consent.ts:237-242), the book row keeps consentState UNKNOWN, and NO enum migration is needed.
- CONTRADICTION in the plan: U31 (line 2154) says 'Consent is never written by an import path', OD10 (line 958) says 'no import path may set consent to granted', and U33 says 'first-party bases write GIVEN ledger rows'. Reconciled: no FILE content can ever grant consent. The only consent an import records is the officer's run-level attestation, written ONLY for numbers the run CREATES, that no player holds, that have no ledger row at all and no active suppression. U31's sentence must be reworded in the same commit.
- FALSE as written: 'the wording is copied onto every row the run creates'. An import GIVEN on a PLAYER's number would become that player's latest ledger row. It is not a pinned SMS sentence, so it would silently turn the player's marketing OFF at the gate (consent.ts:141) and their profile switch OFF (consent.ts:307). An import GIVEN after an erasure would also re-grant the erased person. So player, already-on-record and suppressed numbers get nothing.
- FALSE implicit premise in U11 ('marketable solely when the import recorded an 18+ attestation'): the plan assumes the latest row carries it. After an /s stop → resume, the latest row is the resume sentence (optout-service.ts:288-303) with no attestation. A latest-row-only check would make every resumed contact age_unknown for ever, and would break test:marketing-optout labels 1 and 12 (scripts/marketing-optout.test.mts:355-398, 'a resume gives back EXACTLY the pre-stop answer'). The gate must look back for the attestation, bounded by the number's last erasure.
- FALSE dependency premise: no ContactImport run row exists yet. Neither schema.prisma nor store.ts has it, because U29 is unbuilt. The run-level basis has nowhere to live until U29 lands or U33 adds columns.
- FALSE as stated: 'an explicit 18+ attestation' required for every basis. For the third-party basis nothing is recorded with which an attestation could travel (OD14: 'with the consent'). Decided: for that basis it is not asked and not shown, and the proof note is still required (ETA s.31(c) provenance).
- INCOMPLETE: the board's kind 'engine' (§1 line 564) carries no States line, but §9's text specifies a picker UI inside U30's pre-flighted dialog state. That UI needs states at 1280 and 360.
- No basis wording exists anywhere yet. 'Each option's verbatim stored wording' must be written and pinned by this unit, and it is legal evidence from its first production row.
