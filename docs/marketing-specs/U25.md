## premisesFalse
- 'BOM strip' (plan:2097), and U34's RED 'write the BOM and stop stripping it' (plan:2184-2189), cannot fail as written in the browser. WHATWG TextDecoder and TextDecoderStream default to ignoreBOM:false, which CONSUMES a leading BOM, and Blob.text() also UTF-8-decodes with the BOM removed. A string-level strip is never reached, so its guard and U34's red control are vacuous. FIX: U25 exports DECODE_OPTIONS = {fatal:false, ignoreBOM:true} (true means the BOM is passed through as U+FEFF). Every decode (the test helper decodeBytes, and U32's TextDecoderStream) uses it, so stripBom is the ONE stripper. The suite asserts this (§5.4).
- 'a delimiter vote counted outside quotes, on the header line only' (plan:2097-2098) needs two precisions. (a) 'Outside quotes' depends on the delimiter: a `"` opens a quoted field only at a field start, and what counts as a field start depends on which delimiter you assume. The vote must therefore scan the header once per candidate, each scan with its own quote rules. (b) The 'header line' must be the first NON-BLANK RECORD, not the first physical line. A quoted header cell can contain a newline, and a leading blank line would otherwise vote 'no delimiter'. This refines the rule; it does not reverse it, because the data body still never votes.
- The unit text never mentions streaming, yet §3c.2 (plan:842-843) binds U25 to it. A readFile-then-split parser would pass every fixture the text lists and still break §3c. FIX: the engine is an incremental reader (createCsvReader().push/end). parseCsv is just push(text)+end(). The suite asserts that chunking changes nothing (§4.1) and that each character is tokenized exactly once (§4.2).
- U34 (plan:2184) relies on 'the `'` formula guard that the importer's `unguard` reverses', but no unit's text creates that unguard. U25 takes it on: guardCell/unguardCell live in import-parse.ts, and U34 imports guardCell from there. The transactions guard (route.ts:47, /^[=+\-@\t\r]/) is not an exact inverse: a value that already starts with `'=` cannot be recovered. The contacts pair therefore adds `'` to the set of leading characters, which makes unguardCell(guardCell(s)) === s for every s. The transactions route is left unchanged.
- Encoding is missing from the text. Excel's 'Unicode Text (*.txt)' is UTF-16LE with a BOM, tab-separated, and Excel's 'CSV (Comma delimited)' is windows-1252 on an English Windows PC. A UTF-8-only reader turns the first into NUL-riddled noise and the second into U+FFFD wherever a ’ or an é appears. FIX: sniffEncoding(head) chooses utf-8, utf-16le, utf-16be or windows-1252; rows still holding U+FFFD are counted and named.
- U27 (plan:2114) says 'One ParsedContactsFile shape, two producers', but no unit before U27 defines that shape, and U25 is the first producer. If U25 does not define it, U27 has to retrofit U25. FIX: U25 defines ParsedContactsFile, GridRow and GridSummary as pure types, and U27's server XLSX reader must return the same shape.
- The board's notes (plan:132 'U25+ the importers', plan:550 'no writer until U22/U25') imply that U25 writes contacts. It does not: it is pure and touches no store. The first import WRITER is U29 (staging) and U31/U32 (the commit loop), so U19's live check still waits on U22 or U32.
- The §10 session table (plan:2449-2451) is stale. It lists S10 = U21·U22 and S12 = U25·U26, but S10 actually ran the consent tie, U18b, U19 and U20 (plan:39-94). Do not take U25's session number from the table.

## apis
- export const CSV_DELIMITERS: readonly [",", ";", "\t", "|"] — the vote candidates. This order is also the tie-break order.
- export type CsvDelimiter = (typeof CSV_DELIMITERS)[number]
- export const MAX_FIELD_CHARS = 32_767 — Excel's per-cell limit. A longer field can only be a quote that never closed, and it is FATAL.
- export const MAX_HEADER_CHARS = 1_048_576 — the vote's buffer cap. If the first non-blank record has not ended by then, the file is refused with `header_too_long`.
- export const WARNINGS_KEPT = 50 — at most 50 warnings are kept, and `warningCount` always carries the true total (U32 shows it as 'capped at 50 with the true total beside it').
- export type GridRow = { readonly fileRow: number; readonly cells: readonly string[] } — fileRow is 1-based and counts RECORDS as a spreadsheet shows them. The first record after the optional sep= line is row 1, because Excel consumes sep= and does not show it. Blank records COUNT toward the numbering but are never emitted. A record with a quoted newline is still ONE row. Cells are raw: no trim, no coercion, no unguard. Inside a quoted field, CRLF and lone CR become LF.
- export type CsvProblem = { kind: 'unterminated_quote' | 'field_too_long' | 'header_too_long'; fileRow: number } (FATAL) | { kind: 'stray_quote' | 'inner_bom' | 'delimiters_in_single_column'; fileRow: number } | { kind: 'sep_unsupported'; fileRow: 0; asked: string } (warnings)
- export function csvProblemSentence(p: CsvProblem): string — ONE English sentence per problem, never a code (the admin chrome is English, §5.13). For example, unterminated_quote: 'Row 12 opens a quotation mark (") that is never closed, so everything after it would be read as one cell. Close the quote in row 12 and try again.'
- export type GridSummary = { readonly records: number /* every record including blanks, excluding the sep= line */; readonly emitted: number; readonly blank: number; readonly widest: number; readonly ragged: number /* emitted rows whose cell count differs from the first emitted row's */; readonly replacementRows: number; readonly firstReplacementRow: number | null /* rows containing U+FFFD */; readonly warnings: readonly CsvProblem[]; readonly warningCount: number; readonly fatal: CsvProblem | null } — the part shared by the CSV and XLSX producers.
- export type CsvSummary = GridSummary & { readonly delimiter: CsvDelimiter | null /* null = single column, nothing splits */; readonly delimiterSource: 'sep' | 'vote' | 'single_column' | 'override'; readonly voteRow: number | null; readonly tie: boolean; readonly hadBom: boolean; readonly charsInput: number /* chars after the BOM and the sep= line */; readonly charsTokenized: number /* equals charsInput unless fatal: each char is tokenized exactly once */ }
- export type ParsedContactsFile = { readonly format: 'csv' | 'xlsx'; readonly rows: readonly GridRow[] /* every NON-BLANK record in file order, the first one included: deciding whether row 1 is a header is U28's job, and a headerless list of bare numbers is real */; readonly summary: GridSummary; readonly csv: CsvSummary | null } — the ONE shape. U27's server XLSX reader returns it with csv:null.
- export function stripBom(text: string): { text: string; hadBom: boolean } — strips one U+FEFF at index 0, and nothing else.
- export function readSepDirective(text: string): { delimiter: CsvDelimiter | null; asked: string; length: number } | null — reads Excel's directive, which is valid on the first line only (after the BOM): case-insensitive `sep=X`, optionally wrapped in double quotes, ending at CRLF, LF, CR or end of text. `length` is how many characters to skip. A character outside CSV_DELIMITERS gives delimiter:null plus a `sep_unsupported` warning: the line is still consumed and the vote decides. Returns null when the first line is not a directive, or (while streaming) is still incomplete.
- export type DelimiterVote = { readonly delimiter: CsvDelimiter | null; readonly counts: Readonly<Record<CsvDelimiter, number>>; readonly tie: boolean; readonly complete: boolean }
- export function voteDelimiter(text: string): DelimiterVote — skips blank leading records and scans the FIRST NON-BLANK RECORD once per candidate d. Each scan starts with fieldStart=true. A `"` at a field start opens quotes. Inside quotes, `""` is an escaped quote and a lone `"` closes. Outside quotes, d increments the count and sets fieldStart; CR or LF ends the record. Highest count wins; a tie between non-zero counts goes to CSV_DELIMITERS order with tie:true; all zero gives delimiter:null (a single column). complete is false while any candidate's scan has not reached its record end (a streaming caller keeps buffering). It never reads past the header record.
- export type CsvReaderOptions = { readonly delimiter?: CsvDelimiter } — the mapping panel's manual choice (U28/U30). It overrides both sep= and the vote, giving delimiterSource 'override'.
- export interface CsvReader { push(chunk: string): GridRow[]; end(): GridRow[]; summary(): CsvSummary } — the engine. push returns the records completed so far. It buffers only (a) the start of the stream until stripBom and readSepDirective can decide, and (b) until voteDelimiter(...).complete, re-running the vote only when a chunk contains CR or LF. After that it tokenizes in one pass, carrying its state across chunks: in quotes or not, a pending `"` at the end of a chunk, a pending CR at the end of a chunk, and the partial field and record. After a FATAL problem every later push returns []. A U+FEFF at the start of a later record is dropped and warned as `inner_bom` (Windows `copy a.csv+b.csv` merges). In single-column mode, any record holding a candidate delimiter outside quotes is warned once as `delimiters_in_single_column`, with the first row and the count.
- export function createCsvReader(opts?: CsvReaderOptions): CsvReader
- export function parseCsv(text: string, opts?: CsvReaderOptions): ParsedContactsFile — the one-shot form, i.e. createCsvReader(opts), then push(text), then end(), returning format 'csv'. It serves paste (an Excel copy is TSV), small files and the suite.
- Tokenizer rules for delimiter d: a field is quoted only if its FIRST character is `"`; leading spaces are not skipped, so `a, "b"` gives the literal ` "b"`. Inside quotes, `""` becomes `"`. A `"` followed by d, CR, LF or end of text closes the field. A `"` followed by any other character is a `stray_quote` warning: quotes end, and the rest of the field is appended literally (Excel turns `"abc"def` into `abcdef`). In an unquoted field a `"` is literal (`5" screen`). CRLF, LF and lone CR end a record outside quotes. A trailing newline creates no empty record. A record whose cells are all empty or whitespace (an empty line, `,,,`, or `""`) is blank: counted, never emitted. A field longer than MAX_FIELD_CHARS is fatal `field_too_long`. Quotes still open at end() are fatal `unterminated_quote`, naming the fileRow where that record began; rows before it are emitted and nothing after it.
- export type TextEncodingLabel = 'utf-8' | 'utf-16le' | 'utf-16be' | 'windows-1252'
- export const SNIFF_BYTES = 4096 — the dialog reads file.slice(0, SNIFF_BYTES).
- export const DECODE_OPTIONS = { fatal: false, ignoreBOM: true } as const — ignoreBOM:true passes the BOM through, so stripBom is the ONE stripper. U32 must stream with new TextDecoderStream(encoding, DECODE_OPTIONS).
- export function sniffEncoding(head: Uint8Array): { encoding: TextEncodingLabel; bom: boolean } — checks in this order: EF BB BF gives utf-8 with bom; FF FE gives utf-16le with bom; FE FF gives utf-16be with bom; BOM-less UTF-16 (≥90% of the odd bytes, or of the even bytes, zero in the first 512) gives utf-16le or utf-16be; otherwise new TextDecoder('utf-8', {fatal:true}).decode(head, {stream:true}) succeeding gives utf-8 (stream:true so a character cut at byte 4096 is not an error), and throwing gives windows-1252.
- export function decodeBytes(bytes: Uint8Array, encoding: TextEncodingLabel): string — returns new TextDecoder(encoding, DECODE_OPTIONS).decode(bytes). For tests and small inputs only; the dialog streams.
- export function looksLikeVcard(text: string): boolean — after stripBom and leading whitespace, tests /^begin:vcard/i (a regex, never .toLowerCase().includes).
- export type ImportFileKind = 'csv' | 'vcard' | 'xlsx'; export type FormatRefusal = 'empty' | 'legacy_xls' | 'ods' | 'html' | 'pdf' | 'binary'
- export type DetectedFormat = { ok: true; kind: ImportFileKind; encoding: TextEncodingLabel | null /* null for xlsx */; namedAs: ImportFileKind | null; mismatch: boolean } | { ok: false; refusal: FormatRefusal; sentence: string; namedAs: ImportFileKind | null }
- export function detectFormat(head: Uint8Array, fileName: string): DetectedFormat — CONTENT BEATS THE NAME. Checks in order: 0 bytes, or only a BOM and whitespace, is 'empty'. D0 CF 11 E0 is 'legacy_xls'. 50 4B 03 04 whose first entry is `mimetype` holding application/vnd.oasis.opendocument.spreadsheet is 'ods'; any other zip is kind 'xlsx' (U27's exceljs refuses a non-workbook). %PDF- is 'pdf'. Otherwise the head is decoded with sniffEncoding: a start of `<html`, `<!doctype html`, `<table` or `<?xml` (case-insensitive, after the BOM and whitespace) is 'html' (a web page saved as .xls); looksLikeVcard is 'vcard'; a NUL in a non-UTF-16 head is 'binary'; anything else is 'csv'. namedAs comes from the extension (.csv/.tsv/.txt → csv; .vcf/.vcard → vcard; .xlsx/.xlsm → xlsx; anything else → null), and mismatch = namedAs !== null && namedAs !== kind. Refusal sentences reuse U27's remedy wording ('save it as CSV — there is no size limit on CSV').
- export function guardCell(s: string): string — prefixes `'` when s starts with = + - @ TAB CR or `'`. U34's writer imports it.
- export function unguardCell(s: string): string — removes ONE leading `'` when the next character is in that same set. Its exact inverse property, unguardCell(guardCell(s)) === s for every s, is asserted. U28 applies it once to every cell from either producer. The reader does NOT apply it, so cells stay raw.

## risks
- The Edit and Write tools DECODE escapes (memory: reference_edit_tool_decodes_escapes), and this module is full of them (\t, \r, \n, ﻿, �). Writing it the obvious way can put a raw TAB, CR or BOM into a string literal, which still compiles and looks identical in the editor. Mitigations: write every special character as a numeric char code (String.fromCharCode, or charCodeAt comparisons against 9/10/13/34/44/59/124/0xFEFF/0xFFFD), so the source holds no backslash escapes; §8.1 scans the source for raw control characters and U+FEFF; never author the file through a Git Bash heredoc (memory: reference_gitbash_heredoc_backslash).
- Tailwind scans src/**/*.ts comments (tailwind.config.ts:47). Never write a bracketed class-shaped token in this module's prose: describe the formula-lead set in words or code, not as a `word-[...]` token.
- The suite must contain NO file-write token, even in a comment (writeFileSync, writeFile, rmSync and the like). Otherwise red:contacts-import falls into red-anchors' undeclared count, which is pinned at === 65.
- The sep= row-numbering choice: Excel hides the sep= line, so row 1 is the header. LibreOffice and Google Sheets show it as a row, so a user of those tools sees every row number one higher than ours. This is recorded as a decision, and U30's copy should say 'row numbers as Excel shows them'.
- The header-only vote is wrong on a hand-made `;` file whose first non-blank line is an undelimited title (Excel itself pads titles with delimiters, so its own files are fine). It falls back to single_column with a delimiters_in_single_column warning, and the manual opts.delimiter (U28/U30's chooser) recovers. The warning is what keeps this from failing silently.
- A CSV cell Excel already turned into scientific notation (`2.55713E+11`) is lossy and cannot be recovered. U25 passes it through raw, and parseTzNumber calls it too_short. U28/U30 should give it its own sentence ('Excel shortened this number into scientific notation … format the column as Text and save again'). U27's numeric-cell rule only helps XLSX.
- The windows-1252 fallback is decided from the first 4 KB only. Invalid bytes deeper in the file decode as U+FFFD, and the reader counts and names those rows (replacementRows) rather than guessing again. A UTF-8 file whose first 4 KB is pure ASCII but holds 1252 bytes later shows the same counted U+FFFD rows.
- The vote's buffering is bounded at MAX_HEADER_CHARS (1 MiB). It re-runs the vote only when a chunk holds CR or LF, so 1-character chunks cannot make it quadratic. §4.2 asserts single-pass tokenizing, but the vote's own rescans sit outside charsTokenized by design, so keep them bounded by the header length.
- Bundle and placement: OD29 puts this parser in the browser. Keep it free of server and node imports (§8.1) until U27's structural boundary guard (test:contacts-boundary) exists. Typecheck will NOT catch a server import pulled into a client chunk (memory: feedback_build_is_not_a_render).
- Timing: the 150k-corpus assertions run on a loaded laptop. Assert counts and equality only, never wall-clock time. Run the suite through the heavy-node lock with the rest of the serial battery.
- The guard pair's `'` lead differs from the transactions export (route.ts:47) on purpose. Do NOT 'unify' it by editing the transactions route: it is outside this lane, its CSV is already in officers' hands, and parseTzNumber strips a leading `'` either way.

## guard: test:contacts-import (new suite: True)
- A: §1.1 A plain comma file gives the exact grid (cells and fileRow deep-equal). It fails for a parser that returns one column or drops a row.
- A: §1.2 `"Mwanaisha, Mama",0712 345 678` gives two cells, the first being `Mwanaisha, Mama`. It fails for any splitter that ignores quotes (the invite-service.ts:52 shape).
- A: §1.3 `"Asha ""Mama"" Juma"` gives `Asha "Mama" Juma`. It fails if doubled quotes are not collapsed.
- A: §1.4 An embedded newline inside quotes (both LF and CRLF) gives ONE cell holding a single LF, and the NEXT record's fileRow is exactly +1. It fails if numbering follows physical lines or the record is split.
- A: §1.5 With CRLF line endings, no cell anywhere contains a CR. It fails for an LF-only splitter.
- A: §1.6 Lone-CR line endings (old Mac Excel) split into records. It fails if only LF ends a record.
- A: §1.7 A trailing newline adds no phantom record, and a missing trailing newline still keeps the last record. Either way it fails on an off-by-one.
- A: §1.8 Blank lines, `,,,` and `""` rows are absent from rows, counted in summary.blank, and the row after two blanks carries fileRow +3. It fails if blanks are emitted or numbering skips them.
- A: §1.9 An unquoted `5" screen` stays literal. It fails for a parser that opens quotes mid-field.
- A: §1.10 `"abc"def` gives `abcdef` plus one stray_quote warning naming the row. It fails if the warning is missing or the text is dropped.
- A: §1.11 An unterminated quote at row 4 sets fatal = {unterminated_quote, fileRow:4}, emits rows 1-3 and nothing after. It fails if the rest of the file is silently swallowed into one cell.
- A: §1.12 A 32,768-character field is fatal field_too_long. It fails if there is no cap.
- A: §1.13 Raw cells are untouched: `" 0712 345 678 "` keeps its spaces and `0712345678` keeps its zero. It fails for a reader that trims or coerces (rawInput fidelity, schema.prisma:3328).
