## Premises verified true (16)

- Segments x recipients already has one pure home. planSms(text, recipients) returns billableSegments and deliberately no money (sms-compose.ts:218-233). Its comment says the price per segment 'belongs with the ledger (plan U49)'.
- Sizing already includes the footer. composeMarketing sizes body+footer, never the body alone (footer.ts:131-142). SMS_MAX_SEGMENTS = 1 (sms-compose.ts:91), so today every marketing variant is exactly 1 segment.
- SMS_ARITHMETIC_VERIFIED_AGAINST_BILLER = false (sms-compose.ts:78), so every segment total must still read 'estimated'.
- The raw material for a balance walk exists on every accepted row. SmsMessage.balanceTzs is the accepted reply's figure (schema.prisma:3086-3087; written at sms.ts:796-801). A refused row stores null (sms.ts:805-811), so a refusal's 0.0 never enters the walk.
- Reply balances are PRE-CHARGE (sms.ts:238-241; BLACKBALL-SMS.md:78-79). So for consecutive chunks i and i+1, balance(i) - balance(i+1) is chunk i's charge. That is what makes a walk possible.
- The fresh read exists. refreshSmsBalance({maxAgeMs, budgetMs}) at sms.ts:379-394 answers fresh / reused / pending / failed / unavailable, with stale and error fields (sms.ts:313-327). It shares one read in flight (sms.ts:334-351), remembers a failure for 30 s (sms.ts:149, :391) and never throws.
- SMS_BALANCE_RENDER_BUDGET_MS = 2_500 is exported (sms.ts:152). smsBalanceThresholds() gives the TZS 50 floor kept for login codes (sms.ts:132, :140-142).
- The history read exists in both twins: db.smsMessage.listRecent(limit), newest createdAt first (prisma-dal.ts:3369-3372; store.ts:2438-2439). U39 needs no new db.* namespace, so no new dal-parity section; §20 is the last one (dal-parity.test.mts:1539), and a new one would be §21.
- GROWTH may not read money. Its money.figures cell is 'none' (roles.ts:462-467) and it holds no accounting domain (roles.ts:202-205). OD24's segments-only view is consistent with both axes.
- A .tsx may not ask the read-tier question. read-tiers 4.4 forbids any .tsx except sensitive.tsx from importing canRead/readCell/mayReveal (read-tiers.test.mts:175-196). So the money decision must live in a .ts module, as the transactions export does (route.ts:148 calls mayReveal).
- ADMIN resolves through the read table (D3; read-tiers 2.1/5.3), so the Owner can witness the GROWTH branch on production by setting his own money.figures cell to 'none'. ADMIN bypasses the domain axis (rbac.ts:92-95).
- The pure-view-model pattern exists. smsCreditTile (src/app/admin/system/sms-credit-tile.ts) turns a balance read into strings that a suite drives without rendering. Its fixed-month EAT clock (eatClock) and its compact-above-1,000,000 rule (COMPACT_FROM) can be reused.
- Admin pages take the viewer's role from the STORED user row, not the cookie (admin-section-gate.tsx:70,77; sensitive.tsx viewerRole).
- /api/dev-test/seed-admin mints a GROWTH or ADMIN staff session (seed-admin/route.ts:30-46). The U20 drive's staffCtx('GROWTH', …) is the precedent for a role-split drive.
- Dev routes are enumerated automatically and must 404 in production before their first await (dev-route-guard.test.mts:31-41).
- sms-cost-guard §8 pins only the existing callers of refreshSmsBalance and keeps no closed caller list (sms-cost-guard.test.mts:524-593). A new caller does not turn it red.

## Premises found false (10)

- 'Measured … over recent ACCEPTED sends' is wrong about what is billed. The vendor charges per DELIVERED message: one good number plus one unroutable number were 'accepted whole' and only TZS 6 was charged (BLACKBALL-SMS.md:37 step 3; §5 :438 'TZS 6 per delivered SMS'). A walk over accepted chunks would under-price, which is the dangerous direction. The walk must use only chunks whose every row is DELIVERED.
- 'Segments' cannot be read off a row. SmsMessage has no segments or coding column, only bodyLen = body.length in UTF-16 units (schema.prisma:3074; sms.ts:737). A row is segment-certain only when bodyLen ≤ 70 (SMS_LIMITS.UCS2.single), which is exactly 1 segment in either coding. Longer rows (invites, marketing bodies) cannot be measured without a schema change. U39 deliberately avoids that change.
- 'configured, not yet measured' assumes a configured price exists. None does: no env var, SystemConfig or constant anywhere (grep for SMS_PRICE / SEGMENT_COST / costPerSegment finds nothing). U39 must introduce the optional env SMS_PRICE_PER_SEGMENT_TZS, or say 'not yet measured'.
- sms.ts:238-241 says 'the price is read from the portal, never computed from a reply'. The walk computes it from the DIFFERENCE of two consecutive pre-charge readings, which is a different quantity. That comment must be reconciled in the same commit, or the code contradicts its own record.
- 'never the 15-minute in-process snapshot' is only half separable. refreshSmsBalance reuses the same in-process snapshot when it is younger than maxAgeMs (default 60 s, sms.ts:387), and send replies write that snapshot too (sms.ts:785). So a 'reused' figure can be a pre-charge reply up to one batch (≤ TZS 300) high. U39 uses maxAgeMs 60_000, as Admin → System does; U49's Start check must read tighter.
- 'show unreadable … as Admin → System's tile does' is only half true. On a stale figure the tile headlines '—' but still prints the KEPT figure ('Was TZS 185', sms-credit-tile.ts stale branch). U39 must print NEITHER the figure nor 'was'.
- 'Guard: test:read-tiers' gates nothing on deploy. test:read-tiers exists (package.json:33) but is NOT in predeploy (package.json:300). red:read-tiers is a FILE-MUTATING harness (scripts/red-read-tiers.mjs imports writeFileSync + injectDefect), which §5.11 says to avoid for new controls.
- 'the accounting tier' (OD24) is defined nowhere. The phrase appears only at plan :1006. money.figures is defined as 'any TZS total attributable to one named player' (roles.ts:533-534; READ-TIERS.md:204), and a campaign cost is not per-player. Gating on that class silently widens it unless READ_CLASS_SUMMARY and READ-TIERS §3.5 say so.
- Nothing that U39's duration floor, and its 'covers' line, would naturally lean on exists at S19. There is no SEND_WINDOW_EAT (U13, S21), no slice or pump (U43/U44, S23) and no marketing floor (U49, S26); BATCH_MAX = 50 is the only pace constant (sms-blackball.ts:68). OD19's browser accelerator can run two drivers at once, so a naive floor would not be a floor.
- /admin/campaigns does not exist (no src/app/admin/campaigns; U36/U37/U38 are unbuilt). The surface U39 renders on, the per-variant sizes including the {jina} expansion, and the server count 'will receive' are all assumed from the plan text of U37/U38/U24.

- src/lib/marketing/segment-cost.ts: export function measureSegmentCost(rows: CostWalkRow[], o: { provider: string; now: number; configuredTzs?: number|null }): SegmentCostMeasure. Algorithm: (1) keep provider === o.provider and createdAt within 30 days. (2) A CHUNK is the rows sharing (createdAt, sentAt, balanceTzs) with sentAt and balanceTzs both non-null. (3) Sort chunks by sentAt ascending, ties broken by higher balance first. (4) The pair (c_i, c_i+1) is VALID only when all of these hold: every row of c_i is DELIVERED; every row of c_i has a known segment count; every c_i deliveredAt is ≤ c_i+1.createdAt; no other row of the provider was created, or delivered, inside (c_i.createdAt, c_i+1.createdAt]. 'Other row' covers QUEUED, UNKNOWN, accepted-without-balance and a late delivery of an earlier chunk. Finally Δ = balance_i − balance_i+1 must be > 0. (5) unit_i = Δ / Σ segments(c_i). (6) With ≥ 3 valid pairs, return MEDIAN(unit_i), sends = Σ rows of the used c_i, and spread. Otherwise return configured when configuredTzs > 0, else unknown.

## Risks (12)

- The billing model is only partly measured. Per-delivered billing rests on one observation (BLACKBALL-SMS.md:37). UCS-2 and multi-segment pricing are unconfirmed (§8), and so is per-network pricing. Mitigation: the walk uses only DELIVERED, segment-certain chunks and takes a median, and every money line says 'estimated'.
- Charge timing may be asynchronous: a reply can still show the previous chunk's pre-charge figure. Mitigation: pairs with Δ ≤ 0 are voided and the median absorbs a minority of double-counted pairs. Back-to-back campaign chunks are the noisiest population; sparse OTP traffic is the cleanest.
- The production population is small. Until ≥ 3 valid pairs exist (mostly OTP sends), cost reads 'not yet measured' unless Ali sets SMS_PRICE_PER_SEGMENT_TZS.
- ZH login codes are UCS-2 single-segment. If the vendor prices UCS-2 segments differently, they bias the walk. The median holds while SW/EN dominate; the walk cannot tell the codings apart from bodyLen.
- A 'reused' credit reading (younger than 60 s) can be a send reply's pre-charge figure, at most one batch (≤ TZS 300 at 1 segment) high. Acceptable for an estimate; U49's Start refusal must read tighter.
- The duration floor is a true floor only if the engine keeps ONE slice in flight per campaign. OD19's page accelerator plus the pump could otherwise halve the real time. This is recorded as a requirement on U43 (MAX_SLICES_IN_FLIGHT).
- Adding test:read-tiers to predeploy will block deploys if it is red on main. S10 measured 79/79; re-derive on clean origin/main in the same session before adding it.
- red:read-tiers mutates real files. Run it detached and through ~/heavy-node-lock.sh, and check git status plus a NUL scan after it (memory: a red harness mutates the repo). The new suite's red is in-process.
- The READ_CLASS_SUMMARY wording change is visible to the Owner on /admin/roles. Without it, governing campaign cost by money.figures would be a silent widening of the class (READ-TIERS §3.5a's lesson, in reverse).
- U15's future 'one send path' guard (S20) may enumerate sendBatch callers. The dev seed route calls the real sendBatch; it must 404 in production and refuse any non-loopback BLACKBALL_API_URL, and U15 must allowlist it by name.
- U37 and U38 APIs are assumed: the variant-size context, the shared split promise and the fault switch. If they ship differently, only estimate-section and the page wiring change; the pure and server modules are unaffected.
- No real SMS and no chargeable call: U39 sends nothing in production. Its only outbound call is the free, authenticated balance read (BLACKBALL-SMS.md §1.4). The dev seed route reaches a loopback stand-in only. The first live campaign send stays a separate, Ali-gated step (U52).
