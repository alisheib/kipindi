## Premises found false (11)

- The plan's 'RED: size before appending the footer' is NOT a new control. It already exists at the composeMarketing layer: red:campaign-compose envPlants[0] expects /^§11 ⭐ the size is taken of the WHOLE message/. U37's control has to plant at the NEW layer, the composer's variant counter and screen, or it proves nothing new.
- 'Forced to Unicode by: ’' is not a hint. composeMarketing REFUSES every UCS-2 message (footer.ts:162-167 pushes a problem, so ok is false). UCS-2 is therefore a refused state, and the screen must offer the foldToGsm7 fix.
- Nothing implements a placeholder anywhere: zero '{jina}' handling in src/lib. U35's §9 field list (plan :2197-2200) has NO column for the fallback, and one fallback cannot serve both a Swahili and an English body. Each variant needs its own fallback.
- The literal placeholder cannot be sized as typed. '{' and '}' are GSM-7 EXTENSION characters costing 2 septets each (sms-compose.ts:53), so '{jina}' is 8 septets. A counter that sizes the template as typed under-reserves every name over 8 letters, and an at-budget body becomes 2 segments, which is twice the money, for long names. The counter must size the WORST-CASE name.
- /admin/campaigns does not exist: no route, no ROUTE_DOMAINS row, no SmsCampaign model, no DAL (grep finds zero hits). U35 and U36 are hard prerequisites.
- The test send is the FIRST code able to put a marketing message on the wire. SmsPurpose has no MARKETING (schema.prisma:3028-3032; store.ts:329), and dispatchSlice has no default send (dispatch.ts:36-40). So the owner gate for the first live send must be built HERE, not deferred to U43 or U52.
- A test send to the officer's own number is not automatically allowed. Routed through the one gate (no bypass, which is D15's class), it is refused unless the officer's own account is marketable: toggle plus a pinned-wording GIVEN row, RG standing, a non-null dob (User.dob is nullable, schema.prisma:261; age_unknown at consent.ts:212), and status ACTIVE or PENDING_KYC (consent.ts:89). The plan's text does not anticipate this.
- User.displayName is not a name. It is a self-chosen handle of 1-40 characters of any text (src/app/profile/actions.ts:28; display-label.ts:1-30). Inserting it raw under our sender ID is an abuse vector (a handle like 'www.x.tz' or 'Ali99'). A book contact's name on a recycled number prints the PREVIOUS holder's name.
- OD42's 'per-recipient selection from User.locale' is not a live signal: the language menu never writes the column (OD42 amendment). The variant rule must be ONE pure function, stated on screen in the same words.
- 'Next free dal-parity section §21' is true today, but U37 adds no namespace of its own. U29 (S14) and U35 (S17) run first and will claim §21 and beyond. At most, U37 adds one method line inside U35's section.
- 'A read-only sender line' conflates two things. The handset header is SMS_SENDER_ID (sms.ts:719, env). The body prefix is SENDER_IDENTITY '50pick' (footer.ts:53). The line must show the header and say why it cannot change. In dev, SMS_SENDER_ID may be unset, and the line must say so rather than print blank.
