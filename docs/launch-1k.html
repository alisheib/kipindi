✔ Backup schedules are ON — daily + weekly + monthly snapshots of the database volume, daily + weekly of the cache volume, plus a named baseline snapshot. Cost: cents.

✔ The status page can now say "not ready" — it answers 503 when the database is unreachable, proven both ways by an automated test, live on production.
✔ A spending alarm exists — Railway emails at $75/month. No hard cap (a hard cap would switch production off).
✔ A live credential found committed in the repository was removed (rotate it in Postmark).
⛔ One command is still yours to run — enabling point-in-time recovery: railway postgres pitr enable --service Postgres (~$1–3/mo, a brief database restart, and the recovery window only starts counting once it is on).

Corrections to the 3 September brief — each re-measured, not argued

  • "No member of the public can register today" — false. Registration is phone + password (auth/register/actions.ts); the OTP path is preserved-but-bypassed. SMS remains a launch item for phone verification, not for sign-up.
  • "Proved both ways" on the health fix — overstated. No automated test existed; the manual green exercised the no-database bypass branch. Now: test:health-readiness proves RED (8 assertions, dead DB → 503, no host leak) before trusting any green, and the true-positive branch is proven against production.
  • The "~660 winners" figure was right — re-measured at ~576 at same-region RTT (26 round-trips/winner, current code, scratch DB at production schema). What the brief missed: the failure mode is now a permanent freeze, not a slow grind (full rollback + 5-min retry with zero progress). Detection exists ("Ready to settle" > 0 on /admin/system).
  • "Nothing is cached" — stale. Five server-side cache layers already exist; the genuine gap (leaderboard) is fixed on the phase-2 branch.
  • The branch launch-1k-readiness must never be merged — it is 33 commits behind and carries another session's swept-in work (its own tracker records the git add -A incident). Its one valuable code change was cherry-picked onto main with tests; its docs were rewritten fresh (this file, RAILWAY-LIVE.md).
  • Two API paths in the ops doc rotted within a day: the CLI user token no longer answers billing queries (workspace token now), and railway.json is deprecated and silently ignored (.railway/railway.ts + plan/apply is the home).

Money safety — built, tested, and not rebuilt (re-verified in code 4 Sep)

  • Maintenance mode pauses bets + deposits, withdrawals stay open · payment kill switches per network and direction · deposits settled from a signed re-query, exactly once · dead Redis cannot break a bet · no idempotency key → no automatic retry · 200 simultaneous bets: zero drift · the Up & Down safety net is independent of the game's off switch — every claim confirmed at file:line in the settlement path review.
  • New since the brief: backups are now watched by an alert that arrives (bell + email to every officer), and the volume layer snapshots independently of the nightly.
