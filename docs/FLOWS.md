# Flow architecture — 50pick

Every redirect, gate, and recovery path the platform enforces, with file
anchors. Treat this as the single source of truth when planning new
flows: if a journey isn't listed here, it isn't covered. An anchor is a
file plus the function or constant to search for, never a line number:
line numbers go stale on the next edit, and `test:docs` refuses one.
"The edge" below is `src/proxy.ts`, the gate every request passes before
any route code (Next 16.2 runs it on the Node.js runtime; the word names
its place, not its runtime).

Written 2026-05-17 (Sprint 59.6). **Re-derived from the code 2026-10-06** after the route-audit fixes: section 1 rebuilt, sections 2-8 corrected, all 23 line-number anchors replaced by file + symbol; `test:docs` now checks that every `src/` path named here exists, that no line-number anchor comes back, and that section 1's edge row names exactly `PROTECTED_PREFIXES`. Section 9 keeps its own banner.

## 7. Defence-in-depth layering

For every protected surface, the platform applies **two gates**:

1. **Edge (`src/proxy.ts`)**: before any route code runs, a request for an edge-gated prefix (section 1) whose cookie is missing, forged (the HMAC is verified here, `readVerifiedSession`) or past its 7-day `exp` gets a 307 to sign-in, and an `/admin…` request whose cookie names a non-staff role gets a 307 to `/auth/admin` (W25 belt 1). The edge cannot see idle time, the one-session registry or the live role, and it never runs for a path ending in an image extension (`config.matcher`), which is why step 2 is never skipped. **Corrected 2026-10-06:** this said forged cookies pass the edge.
2. **Page/action layer**: `currentSession()` (signature, 7-day cap, 24 h idle, the one-active-session registry) inside the page or action, plus the stored-row role check on `/admin` (section 3). An ended session is told why through `/auth/session-ended`; a Server Action with no session names its page (`signInPathForAction`). Admin server actions open with a recognised gate (`requireStaff(domain)` or `requireAdminOrThrow`, then the authenticator step-up; `test:admin-action-gate`).

For RG gates, the check lives in the **service layer**: `isLockedOut()` in `deposit()`, in `buyPositionInner()`, in the late deposit settlement (a deposit that lands during a break is held for return, never credited) and on the cash incentive path (`creditInternal()`); `checkDepositLimit()` on deposits; `checkLossLimit()` and `checkSessionTimeLimit()` on bets. **Corrected 2026-10-06:** this said withdrawals go through the same check. They do not, on purpose: a player on a cooling-off break can still withdraw, and a self-exclusion stops withdrawals through its wallet freeze (`src/lib/server/wallet-freeze.ts`).

## 9. House liquidity gates

🟢 **Live on production.** `placeHouseBet` and these gates are on `main`; the engine's `src/lib/server/house-bot/fire.ts` is its only caller, and the owner first switched the desk on on 2026-09-21. The design authority is [`HOUSE-BOTS.md`](HOUSE-BOTS.md); this table is PLAN §3 as amended by N1 §3, N2 §3 and A7, A9, A12 and A15 (`plans/house-bots/04-amendments.md`). ⚠️ It was written at build commit 2 (2026-09-14) and has not been re-derived since: where it and `market-service.ts`'s `// SEAM:` sites disagree, the code wins.

A house bet goes through the same service as a player's bet (`buyPositionInner`) with a `house` bet context, and these checks run in this order. The first failing check returns. Lock order is `wallet:<botUser>` → `market:<id>` → `house:control`, and a house bet sets `lock_timeout` 2 s before the market and control locks. Every kind-specific check reads the claimed intent row by id, never a call argument.

| Step | Where | Check → refusal |
|---|---|---|
| H0 | First, before any lock | An ordered rule, and the intent's status is never part of it. 1. The key must equal `houseIntentKey(intentId)` and there must be no `playStartedAt`, else `house_key_mismatch`. 2. Pre-lookup: the key found with the same user and bot returns the original result with `replayed: true`; found with another user or bot → `house_key_mismatch`; not found → continue. 3.
